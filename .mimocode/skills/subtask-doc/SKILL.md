# Subtask Document Generator Skill

为新的开发任务生成符合项目规范的子任务文档。

## 适用场景

当开始新的任务模块时，使用本 Skill 生成详细的子任务文档。

## 检测条件

用户提出以下需求时触发：
- "规划任务 X 的实施步骤"
- "为 XXX 功能写设计文档"
- 项目规划阶段需要细化任务
- 任务开始前需要明确验收标准

## 核心步骤模板

### 步骤 1：收集任务信息

1. **任务目标**：
   - 要实现什么功能？
   - 解决什么问题？
   - 核心需求有哪些？

2. **API 设计**（如果是 API 任务）：
   - 端点列表（方法 + 路径）
   - 请求体格式
   - 响应格式
   - 鉴权需求

3. **依赖关系**：
   - 前置依赖（哪些任务必须先完成）
   - 后续依赖（哪些任务依赖本任务）

### 步骤 3：填充内容

根据收集的任务信息，填充以下关键章节：

1. **任务目标** - 清晰描述要实现的功能
2. **API 端点** - 列出所有端点（如果适用）
3. **实现步骤** - 分解为可执行的小步骤
4. **验收标准** - 明确的完成标志
5. **测试用例** - 包含单元测试和手动测试

**命名规则**:

- 示例：`subtask-07-doh-api.md`、`subtask-08-detect-api.md`

## 常见问题排查

**Q: 文档应该多详细？**
- 实现步骤要详细到可以直接编码
- 代码示例要包含关键逻辑
- 测试用例要覆盖所有场景

**Q: 如何确定任务分解粒度？**
- 每个步骤应该是可在 1-2 小时内完成的
- 如果步骤太多，考虑拆分任务
- 如果步骤太少，考虑合并相邻任务

**Q: 如何验证文档质量？**
- 按照文档实现功能，看是否顺畅
- 检查是否有遗漏的细节
- 确认新开发者能看懂并执行
