# Workflow Audit Skill

定期复盘用户的工作历史，识别值得沉淀为 Skill、Subagent 或 Automation 的重复性工作流。

## 适用场景

当用户提出以下需求时，使用本 Skill：

- "帮我看看最近有哪些重复工作可以自动化"
- "我想把一些常用操作打包成 Skill"
- "最近花了很多时间在 XXX 上，有没有更好的方法"
- 主动发起工作流优化复盘

## 分析范围

默认回顾 **最近 30 天** 的工作历史（若不足 30 天则使用全部可用历史）。

## 证据优先级

按以下顺序收集和分析证据：

1. **最近的编程会话和任务摘要** - 最直接的行为记录
2. **现有的 Skills、Custom Agents、自动化任务** - 避免重复造轮子，优先复用或扩展
3. **Git 提交历史** - 识别重复的 commit 模式
4. **文件变更记录** - 发现频繁修改的文件类型
5. **对话历史中的明确请求** - 用户多次提出的同类需求

## 识别特征

广泛留意具备以下特征的工作：

| 特征 | 说明 |
|---|---|
| 重复发生 | 至少出现过 2 次，或明显会再次发生 |
| 耗时 | 单次执行超过 10 分钟 |
| 易出错 | 需要人工检查或容易疏忽 |
| 上下文成本高 | 每次都需要重新理解背景 |
| 能从固定流程中受益 | 有明确的输入、步骤、输出 |

## 候选项筛选标准

只对**同时满足**以下条件的候选项采取行动：

- ✅ **重复性**：至少出现过两次，或明显会再次发生且每次重复代价不小
- ✅ **稳定性**：拥有稳定的输入、可重复的流程，以及明确的输出或停止条件
- ✅ **改进空间**：能在速度、质量、一致性或可靠性方面带来实质性改进
- ✅ **缺失覆盖**：现有资产尚未充分覆盖

## 输出形式选择

根据工作流的性质，选择**最小够用**的形式：

| 形式 | 适用场景 | 示例 |
|---|---|---|
| **Skill** | 可复用的工作流或操作手册（playbook） | "Base64 注入方案"、"Git 子模块检查" |
| **Custom Subagent** | 边界清晰、适合委派的专家角色或调研任务 | "技术文档查询助手"、"代码审查专家" |
| **Automation** | 定时或周期性的检查、报告、提醒或监控 | "每日构建检查"、"依赖更新提醒" |
| **Skip** | 过于零散、模糊、敏感，或证据不足以打包 | 临时性调试、一次性任务 |

## 执行流程

### 步骤 1：收集证据

```
1. 读取最近 30 天的任务摘要和对话历史
2. 扫描现有 Skills 目录（/.opencode/skills/ 或 ~/.config/opencode/skills/）
3. 检查 Git 提交历史（git log --oneline -50）
4. 识别高频文件变更模式
```

### 步骤 2：生成候选清单

以表格形式列出所有候选项：

| # | 重复出现的工作流 | 佐证与日期 | 频率/置信度 | 推荐形式 | 为什么值得/不值得 |
|---|---|---|---|---|---|
| 1 | ... | ... | ... | ... | ... |

### 步骤 3：做出创建决策

- **立即创建**：高置信度（≥80%）且确实缺失的项
- **暂缓创建**：需要更多证据（出现次数不足、场景未稳定）
- **跳过**：与现有资产重叠、过于零散、或改进空间有限

### 步骤 4：创建资产（如适用）

仅创建那些高置信度且确实缺失的项。保持它们：
- **聚焦**：单一职责，解决特定问题
- **实用**：有明确的步骤和示例
- **来源清晰**：基于真实工作场景
- **易于验证**：有明确的验收标准

### 步骤 5：总结报告

```markdown
## 本次审计总结

### 已创建/扩展的资产
- [列出本次创建的 Skills/Subagents/Automations]

### 刻意跳过的候选项
| 候选项 | 跳过原因 |
|---|---|
| ... | ... |

### 需要更多证据的候选项
| 候选项 | 缺失证据 |
|---|---|
| ... | ... |
```

## 输出模板

### 候选清单（表格）

| # | 重复出现的工作流 | 佐证与日期 | 频率/置信度 | 推荐形式 | 评估 |
|---|---|---|---|---|---|
| 1 | **工作流名称** | 具体证据（如"在两个独立分支上重复实施"） | 高/中/低 + 百分比 | Skill/Subagent/Automation/Skip | ✅值得 / ⚠️需观察 / ❌跳过 |

### 创建决策

```markdown
#### ✅ 创建：Skill - `skill-name`

**理由**：
- 在本次任务中重复实施 N 次
- 解决了 XXX 核心痛点
- 方案成熟稳定
- 现有 Skills 中无类似资产

**内容框架**：
1. 适用场景检测
2. 核心步骤模板
3. 常见问题排查
4. 验证清单
```

### 跳过说明

```markdown
### 跳过或暂缓的候选项

| 候选项 | 原因 |
|---|---|
| XXX | 与现有 Skill `YYY` 重叠 |
| ABC | 仅出现 1 次，需更多证据 |
```

## 注意事项

1. **不要凭空臆测**：所有候选项必须基于真实证据
2. **不要相互重叠**：避免创建职责重复的资产
3. **不要边界过宽**：每个 Skill 应聚焦单一场景
4. **优先扩展现有资产**：如果已有类似 Skill，优先扩展而非新建
5. **保持克制**：宁可少创，不要滥创
